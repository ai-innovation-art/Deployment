    The running example

    Every module and every lab uses one running example: the reliability-api service — a small FastAPI app you build, containerize, deploy, observe, scale, break, and automate. Using the same app across all modules means every concept is concrete, not abstract.

    📦 Module 02 — Docker

    Build the image, run a container, explore volumes and networks, write a production-grade Dockerfile.

    ☸️ Modules 03–06 — Kubernetes

    Deploy to a local kind cluster, add probes and resource limits, package with Helm.

    📊 Module 07 — Observability

    Scrape with Prometheus, visualize in Grafana, define SLIs and error budgets.

    🚀 Module 09 — CI/CD

    Gate PRs with GitHub Actions, build and push to GHCR, run kind integration tests in CI.

    How to use this site

    1. Read the course note for a module — understand the concept, the diagram, how it applies to reliability-api.
    2. Do the corresponding lab — run real commands, observe real output, note differences from the sample.
    3. Break something on purpose — the failure cases sections and lab sections guide you.
    4. Record what you observe in your study notes.
    5. Check the self-check questions and tick Done in the module topbar.
    GitHub Codespaces

    All lab commands are designed to run in GitHub Codespaces — Docker is pre-installed, you get a full Linux environment in your browser, and nothing breaks your local machine. Open the repo in Codespaces and every docker command works immediately.
