    Request trace: iptables and DNS

    The path of one click

    browser → Codespace:8080 → [Docker port map] → node:30080
 → iptables KUBE-NODEPORTS → KUBE-SVC(web) → 50/50 → DNAT → web pod:8080
 → nginx proxy_pass menu-api:8000 → resolv.conf search → CoreDNS → 10.96.x.x
 → iptables KUBE-SVC(menu-api) → 1/3 each → DNAT → menu-api pod:8000
 → redis:6379 (cache, 30 s TTL)
    Key idea

    No Kubernetes component sits in the traffic path. kube-proxy writes iptables rules ahead of time, CoreDNS answers names, and the kernel forwards packets pod to pod. A Service is a set of rewrite rules on every node.

    Commands, one per hop

    # ① host port → node
docker ps --filter name=quickbite-control-plane --format '{{.Names}}  {{.Ports}}'

# ② NodePort rule
docker exec quickbite-control-plane iptables-save | grep 30080

# ③ Service → pods (load balancing)
docker exec quickbite-control-plane iptables-save | grep "quickbite/web:http"
kubectl get endpointslices -n quickbite -l kubernetes.io/service-name=web

# ④ DNS
kubectl exec deploy/web -n quickbite -- cat /etc/resolv.conf
kubectl run dns --rm -it --restart=Never --image=busybox:1.36 -n quickbite -- \
  nslookup menu-api.quickbite.svc.cluster.local

# ⑥ cache
kubectl exec deploy/redis -n quickbite -- redis-cli TTL menu:1.0

    iptables

    • The Linux kernel's packet rulebook. iptables-save prints all rules. Rules live on each node (kind: docker exec <node>; real server: sudo iptables-save).
    • kube-proxy (on every node) watches Services + EndpointSlices and rewrites the rules. Every node has the same rules, so any node can reach any pod.
    • Read a rule: -A <chain> append · --comment "ns/svc:port" which Service · -j <chain> jump.
    ChainMeaning
    KUBE-NODEPORTSWhich NodePort was hit
    KUBE-EXT-<hash>External traffic for a Service
    KUBE-SVC-<hash>The Service: picks an endpoint (same hash links the chains)
    KUBE-SEP-<hash>One per pod (Service EndPoint)
    DNAT --to-destinationRewrite destination to podIP:targetPort
    KUBE-MARK-MASQAlso rewrite the source (e.g. pod calling itself via its Service)
     
    2 pods:  0.5 → rest
3 pods:  0.333 → 0.5 → rest       = 1/3 each
4 pods:  0.25 → 0.333 → 0.5 → rest
rule k gets 1/(pods remaining). The last rule has no probability.

    DNS

    search quickbite.svc.cluster.local svc.cluster.local cluster.local
nameserver 10.96.0.10      # CoreDNS (kube-dns Service)
options ndots:5            # < 5 dots → try the search list first
    NameWorks from
    menu-apiSame namespace
    menu-api.quickbiteAny namespace
    menu-api.quickbite.svc.cluster.localAnywhere (full name, no search needed)
    postgres-0.postgres.quickbite.svc.cluster.localOne StatefulSet pod (headless)
    • Normal Service → returns the ClusterIP (10.96.x.x). Headless → returns pod IPs (10.244.x.x).
    • busybox nslookup prints NXDOMAIN for every search suffix it tries. That's noise; read the Address: line. Use the full name to avoid it.
