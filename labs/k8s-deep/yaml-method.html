    YAML: commands cheat sheet

    The 5 steps

    # 1. Find the kind, apiVersion, and whether it's namespaced
kubectl api-resources | grep -i deployment

# 2. Generate a template (then delete creationTimestamp, {} and status)
kubectl create deployment menu-api --image=nginx --replicas=3 --dry-run=client -o yaml > my.yaml

# 3. Find where a field goes, and its type
kubectl explain deployment.spec.template.spec.containers
kubectl explain deployment --recursive | less

# 4. Validate against the real API server (nothing is created)
kubectl apply -f my.yaml --dry-run=server

# 5. Compare with what's running, then apply
kubectl diff -f my.yaml
kubectl apply -f my.yaml

    Generators: Namespace, ConfigMap, Secret

    kubectl create namespace quickbite --dry-run=client -o yaml > ns.yaml

kubectl create configmap quickbite-config -n quickbite \
  --from-literal=DB_HOST=postgres --from-literal=CACHE_TTL_SECONDS=30 \
  --dry-run=client -o yaml > cm.yaml

kubectl create secret generic postgres-credentials -n quickbite \
  --from-literal=username=quickbite --from-literal=password=quickbite-dev-password \
  --dry-run=client -o yaml > secret.yaml

    Remember

    ConfigMap values are plain text. A Secret's stringData is plain text, and its data must be base64 (echo -n 'pw' | base64). base64 is encoding, not encryption.

    Service and StatefulSet

    Service typeGives you
    ClusterIP (default)One fixed virtual IP, inside the cluster only. Load-balances across pods
    clusterIP: None (headless)No virtual IP. DNS returns the pod IPs directly
    NodePortClusterIP + a port (30000–32767) open on every node
    LoadBalancerNodePort + a cloud load balancer
     
    StatefulSet  spec.selector.matchLabels ──must match──► spec.template.metadata.labels (pod labels)
Service      spec.selector             ──must match──► the same pod labels

Service DNS: postgres.quickbite.svc.cluster.local              (5 parts)
Pod DNS:     postgres-0.postgres.quickbite.svc.cluster.local   (6 parts, StatefulSet + headless only)
    • serviceName (StatefulSet) must name a headless Service. It gives each pod its DNS name.
    • Pods are named <name>-0, -1, -2, created in order. Each pod gets its own PVC, and keeps it when replaced.
    • Replicas are separate databases. Copying data between them is the database's job (an operator), not Kubernetes'.
    • clusterIP and selector can't be changed later: delete and recreate.
    • metadata.labels = tags on this object. spec.selector = a search for pods.
    4-line summary

    1. Labels tag pods. Selectors find pods by those tags.
    2. If the StatefulSet/Deployment selector doesn't match the template labels, apply is rejected (loud error).
    3. If the Service selector doesn't match, the pod runs but has 0 endpoints (silent error). Check kubectl get endpointslices.
    4. Headless means DNS returns the pod IP directly. With a StatefulSet, each pod gets pod.service.ns.svc.cluster.local.

    Container: env, probes, resources

    env:
  - { name: X, value: "fixed" }
  - { name: X, valueFrom: { configMapKeyRef: { name: <cm>,     key: <key> } } }
  - { name: X, valueFrom: { secretKeyRef:    { name: <secret>, key: <key> } } }
  - { name: X, valueFrom: { fieldRef: { fieldPath: spec.nodeName } } }
    • The app decides the variable names. You only supply values. A wrong cm/secret name or key gives CreateContainerConfigError.
    • exec has no shell. Use sh -c "..." when the command needs $VAR.
    • containerPort is documentation, like EXPOSE. Name it so Services can use targetPort: <name>.
    ProbeFails →
    readinessRemoved from endpoints (no traffic). No restart
    livenessContainer restarted. Keep it gentler than readiness (initialDelaySeconds)
    startupHolds the other two until the app has started

    Defaults: initialDelay 0 · period 10 · timeout 1 · failureThreshold 3. No liveness is fine. A crashed process is restarted anyway.

    requestslimits
    Used byScheduler (placement)Kernel (runtime cap)
    Over the limit—CPU throttled · memory OOMKilled

    100m = 0.1 core · Mi/Gi binary. QoS: Guaranteed (requests = limits) · Burstable · BestEffort (nothing set, evicted first).

    Storage

    PVC           the request: "1Gi, RWO"     (namespaced)
PV            the actual disk             (cluster-wide)
StorageClass  how disks are made          (kind default: standard / local-path)

volumeClaimTemplates name "data" + pod postgres-0  →  PVC data-postgres-0
    • Access modes: RWO (one node) · ROX · RWX (needs NFS) · RWOP (one pod).
    • Deleting a pod or StatefulSet keeps the PVC. Delete it yourself.
    • local-path disks live on one node, so the pod is pinned to that node.
    • Delete the pod → same name, same node, same disk, same data.

    Ports

    laptop:8080 ──► hostPort 8080   kind extraPortMappings (only kind)
           ──► nodePort 30080   open on EVERY node (Service type NodePort)
           ──► port 80          Service port: what pods dial (web:80)
           ──► targetPort 8080  container's port inside the pod
               containerPort    documentation of that same port
    • targetPort is NOT a host port. It's the port inside the pod. It defaults to port and can be a name.
